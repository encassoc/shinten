# 例：漏れても読めない注文フォーム

公開済みのパッケージで作った、架空のネットショップのデモです（画面は日本語）。
shinten が注文フォームをブラウザで暗号化します。
[shinten-ship](https://github.com/eucassoc/shinten-ship) が出荷担当の端末で復号して、
配送会社の取込ファイルを作ります。
[deedlog](https://github.com/eucassoc/deedlog) が各手順を記録し、二つの連署サーバーが連署します。

流れは [demo.mp4](demo.mp4)（約2分）で見られます。

## 動かし方

Node 20 以上と、`dlog` をビルドするための Go が必要です。

```sh
git clone https://github.com/eucassoc/deedlog && (cd deedlog && go install ./cmd/dlog)

cd examples/web-shop
npm install
npm start          # http://127.0.0.1:8800/
```

`dlog` が `PATH` にない場合は `DLOG=/path/to/dlog` を指定します。鍵と記録は
`state/`（または `STATE`）に書き出されます。連署サーバーは 8811 番と 8812 番のポートで
動きます。起動するたびに、また「最初から」を押すと、空の状態から始まります。

## 見られること

画面下のバーでページを切り替えます。

1. **お客さまの画面**：お店の注文フォームです。お名前・ご住所・お電話番号を、
   ブラウザの中で、出荷担当の鍵と控えの鍵に向けて暗号化します。鍵は
   `/.well-known/shinten.json` で配られます。郵便番号は送料計算のため暗号化しません。
2. **管理画面**：お店のサーバーにあるのは、郵便番号と暗号文だけです。
3. **漏洩を想定**：データベースが持ち出された場合の `orders` テーブルです。
   復号する鍵はサーバーにありません。
4. **出荷担当の端末**：復号してヤマト運輸 B2クラウドの取込ファイルを作ります。
   印刷が済んだら削除します。
5. **運用証跡**：受付・復号・削除が deedlog の記録になります。記録に個人情報は
   入りません。「記録を検証する」を押すと、チェックポイントに署名し、二つの連署サーバーの
   連署を受け、`dlog verify` で検証します。
6. **サイトが乗っ取られる**：乗っ取りを想定し、サイトが見知らぬ鍵も配り始めます。
   次の注文はその鍵にも向けて暗号化されます。出荷担当の端末は承認していない鍵を
   見つけて、送り状を1枚も作らずに止まります。止めたことも記録に残ります。
